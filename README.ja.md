**iroha** は、Claude Code と Codex のためのローカルファースト Engineering Memory Graph です。エージェントとのセッションで生まれた決定やルール、試行錯誤の末にたどり着いた知見を、検索できて Git でも追える知識ベースに変え、チーム全員で共有します。しかも、人間が「よし」と承認するまでは何も書き込まれません。

AI は驚くほど賢いのに、前回いっしょに何を決めたかはきれいさっぱり忘れます。iroha はその物忘れを直す装置です。承認された知識には出どころ（元になったセッション・Pull Request・コミット・レビュー）が必ず付いてくるので、エージェントは MCP 経由でそれを検索し、「なぜこのコードはこうなっているのか」を最初から分かった状態で次の作業に入れます。

## iroha を使う理由

- **エージェントがもう忘れない。** あるセッションで決めたことや規約が、出どころ付きで次のセッションに引き継がれます。Claude Code と Codex をまたいでも、記憶はちゃんと共有されます。
- **最後に決めるのは、いつも人間。** エージェントが出してくるのは、あくまで知識の「候補」です。残す価値があるものだけを、あなたが承認します。エージェントが「これ大事っぽいです！」と勝手に書き込むことはありません。承認された知識だけが `.iroha/` 配下の正準 Markdown になり、Git にコミットされてチームに共有されます。
- **ローカルファースト、既定でプライベート。** クラウドアカウントも、テレメトリも、どこかのサーバーもありません。生のプロンプトやトランスクリプトが知識ベースに書き込まれることもありません。外に通信するのは、あなたが自分でオプトインした 2 つの機能だけ。埋め込み生成（Voyage）と GitHub forge 連携で、どちらも鍵を設定して有効にするまでは一切動きません。
- **設定ゼロでも検索は動く。** 全文検索とグラフ検索は最初から使えます（日本語などの CJK テキストもOK！）。設定でセマンティック検索を有効にして埋め込み用の鍵を用意すれば、そちらも使えます。どちらか欠けていても、黙って全文検索に戻るだけ。エラーで止まったりはしません。

ちなみに iroha は、誰かを監視したり生産性をランク付けしたりするツールではありません。あくまで、あなた自身が持ち主の「記憶のグラフ」です。

## 動作要件

- **Node.js** `>=24 <25`
- **Git** — iroha は Git リポジトリの上で動きます
- **Claude Code** `>=2.1.198` と **Codex** `>=0.144.5` のどちらか、または両方

## インストール

iroha は `@iroha-labs/iroha` という 1 つの npm パッケージとして配布され、`iroha` バイナリを提供します。このバイナリが CLI・ライフサイクルフック・MCP サーバーのすべてを動かす本体です。だからまずはこれを入れる、それが唯一の必須ステップです。

```bash
npm install -g @iroha-labs/iroha
```

あとは、好きな Git リポジトリの中で次を実行するだけ。

```bash
iroha init      # .iroha/ とローカルインデックスを作成（何度実行しても安全。結果はコミットしよう）
iroha doctor    # Node・Git・検出されたエージェント・データベース機能をチェック
```

`iroha` CLI（`init | sync | search | dashboard | doctor`）は、これ単体で完結して動きます。以下のプラグインは、その上にエディタ連携を乗せるものです。

## エージェントの設定

プラグインは、iroha のスキル・ライフサイクルフック・MCP サーバーをエージェントに登録します。どちらのプラグインも、グローバルに入れた `iroha` バイナリを呼び出すので、先に上のインストールを済ませておいてください。

### Claude Code

```text
/plugin marketplace add iroha924/iroha
/plugin install iroha@iroha
```

スキルは `/iroha:init`、`/iroha:sync`、`/iroha:search`、`/iroha:checkpoint`、`/iroha:dashboard`、`/iroha:doctor` として使えます。

### OpenAI Codex

```bash
codex plugin marketplace add iroha924/iroha
```

追加した marketplace から、お使いの Codex のバージョンに合った手順（Codex CLI の `/plugins`）で `iroha` プラグインをインストールします。Codex はプラグインのフックを自動では信頼してくれないので、`/hooks` を実行して明示的に信頼してあげてください。信頼するまでの間も、MCP サーバーと CLI はちゃんと動きます。Codex のスキルは `$init`、`$sync` のように呼び出します。

インストール・更新・アンインストールの詳しい手順（Codex のフック信頼フローを含む）は [docs/install.md](./docs/install.md) にまとめてあります。

## クイックスタート

プラグインを設定したら、あとは「いつも通り作業して、あとで整える」だけ。

```bash
# 1. いつも通りエージェントと作業します。iroha のフックがセッションを観測し、
#    覚えておく価値のあること（決定・ルール・教訓）が出てくると、エージェントが
#    MCP サーバー経由でそれを候補として提案してくれます。

# 2. ローカルダッシュボードで候補をレビューして承認します。
iroha dashboard
#    → http://127.0.0.1:<port>/#token=… が開きます。残したいものを承認しましょう。

# 3. 承認された知識は .iroha/ 配下の正準 Markdown になります。これをコミット。
git add .iroha && git commit -m "chore: approve knowledge"

# 4. あとはいつでも記憶を検索できます（エージェントは MCP 経由、あなたは CLI から）。
iroha search "なぜ repository パターンを使うのか"
```

リポジトリを clone したチームメンバーは、`iroha init` のあとに `iroha sync --rebuild` を実行すれば、コミット済みの `.iroha/` からローカルインデックスを丸ごと作り直せます。

## 承認ダッシュボード

`iroha dashboard` は、ローカルの単一オリジンアプリを 1 つの loopback ポートで配信し、ブラウザにワンタイムの launch token を渡します。ここで知識の候補をレビューし、それぞれの出どころとつながりを確認して、承認するか却下するかを決めます。承認できるのはこのダッシュボードだけ。人間だけの操作で、エージェントの手はここには届きません。ダッシュボードは loopback にしかバインドしないので、外の世界には一切出ていきません。

## 設定

`iroha init` は `.iroha/config.yaml` を書き出します。ここに書かれるのは**環境変数の名前**だけで、秘密の値そのものは入りません。値は実行時に環境から読むだけで、保存もログ出力もコミットもされません。

| 環境変数 | 用途 | 必須 | 未設定のとき |
|---|---|---|---|
| `VOYAGE_API_KEY` | Voyage によるセマンティック（ベクトル）検索の埋め込み | いいえ | 全文検索とグラフ検索だけになる |
| `GITHUB_TOKEN` | GitHub forge 連携（Pull Request・レビュー）の同期 | いいえ | forge 連携が無効になるだけ |

ただし、鍵を設定しただけでは有効になりません。どちらの機能も **`config.yaml` では既定でオフ**だからです。セマンティック検索には `search.embedding.enabled: true` と `VOYAGE_API_KEY` を、GitHub 連携には `forge.enabled: true` と `GITHUB_TOKEN` を、それぞれ設定してください。

`config.yaml` の主な設定はこちら。

- `default_language` — `en`（既定）または `ja`。ダッシュボードの起動時ロケール。
- `canonical.require_human_approval` — `true` のままにしておけば、レビューを通さない限り何も正準化されません。

## 仕組み

1. **アダプタが両方のエージェントを正規化する。** Claude Code と Codex のセッションは同じドメインイベントに変換され、1 つの記憶グラフが両方を面倒みます。
2. **知識は作業の途中で捉える。** セッションの最後にまとめて要約するのではなく、Turn/Checkpoint のライフサイクルの中で拾います（Codex にはセッション終了フックがない、という事情もあります）。
3. **候補は必ず出どころを持つ。** 提案される決定・ルール・洞察は、それぞれ元のソースと関連項目にひも付きます。
4. **人間が承認する。** 承認された知識は `.iroha/` 配下の正準 Markdown に書き込まれ、コミットされます。これがチームで共有する、信頼できる情報源になります。
5. **ローカルの libSQL インデックスが検索を支える。** 全文検索は常に有効、セマンティック検索は埋め込みを有効化して鍵を設定したときに使えます。このインデックスは使い捨てで、いつでも `.iroha/` から作り直せます。壊れても平気なので、雑に扱ってOK。承認済み知識の唯一の情報源になることは決してありません。

## よくある質問

**データが外に出ることはある？** 基本、ありません。iroha はローカルファーストで、クラウドアカウントもテレメトリもなし。外と通信するのは、あなたが自分の鍵でオプトインしたときだけ。セマンティック検索の埋め込み（Voyage）と GitHub forge 連携の 2 つで、有効にするまでは 1 バイトも出ていきません。

**埋め込み用の鍵がなくても使える？** はい、使えます！全文検索とグラフ検索は設定ゼロで動き、日本語などの CJK クエリにもちゃんと対応します。セマンティック検索は、あくまで「あるとうれしい」追加機能です。

**知識はどう保存されるの？** `.iroha/` 配下に、Git 管理された素の Markdown として保存されます。ほかのソースコードと同じように読めて、差分の確認もレビューもできます。`.git/iroha/` 配下の libSQL インデックスのほうは、ただの使い捨てキャッシュです。

**インデックスを作り直すには？** `iroha sync --rebuild` を実行します。clone した直後は、先に `iroha init` を忘れずに。

**名前の由来は？** *いろは* は、すべての仮名を一度ずつ使う「いろは歌」の冒頭。転じて「物事の基本・いろは」を指します。エンジニアリングの記憶も、まずは基本から。

## セキュリティ

フックによる強制は「ガードレール」であって、完全なセキュリティ境界ではありません。厳密な強制は CI が担います。脆弱性を見つけたら、公開の issue ではなく [security advisory](https://github.com/iroha924/iroha/security/advisories/new) からそっと教えてください。
