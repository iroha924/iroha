**iroha** は、Claude Code と Codex のための **Engineering Memory Graph**（エンジニアリングの知識を貯めて、つなげて、検索できるようにする仕組み）です。しかも、すべてあなたのマシンの中だけで完結する「ローカルファースト」設計。エージェントとのセッションで生まれた決定やルール、苦労して見つけたコツを、検索できて Git でも追える知識ベースに変え、チーム全員で共有します。人間が「よし」と承認するまでは、何も書き込まれません。

AI は驚くほど賢いのに、前回いっしょに何を決めたかはきれいさっぱり忘れます。iroha はその物忘れを直す装置です。承認された知識には出どころ（元になったセッション・Pull Request・コミット・レビュー）が必ず付いてくるので、エージェントは MCP 経由でそれを検索し、「なぜこのコードはこうなっているのか」を最初から分かった状態で次の作業に入れます。

## iroha を使う理由

- **エージェントがもう忘れない。** あるセッションで決めたことや規約が、出どころ付きで次のセッションに引き継がれます。Claude Code と Codex をまたいでも、記憶はちゃんと共有されます。
- **最後に決めるのは、いつも人間。** エージェントが出してくるのは、あくまで知識の「候補」です。残す価値があるものだけを、あなたが承認します。エージェントが「これ大事っぽいです！」と勝手に書き込むことはありません。承認された知識だけが `.iroha/` の下に正式な Markdown ファイルとして保存され、Git にコミットされてチームに共有されます。
- **ローカルファースト、既定でプライベート。** クラウドアカウントも、テレメトリも、どこかのサーバーもありません。生のプロンプトやトランスクリプトが知識ベースに書き込まれることもありません。外に通信するのは、あなたが自分でオプトインした 2 つの機能だけ。埋め込み生成（Voyage）と GitHub 連携で、どちらも鍵を設定して有効にするまでは一切動きません。
- **設定ゼロでも検索は動く。** 全文検索とグラフ検索は最初から使えます（日本語などの CJK テキストもOK！）。設定でセマンティック検索を有効にして埋め込み用の鍵を用意すれば、そちらも使えます。どちらか欠けていても、黙って全文検索に戻るだけ。エラーで止まったりはしません。

ちなみに iroha は、誰かを監視したり生産性をランク付けしたりするツールではありません。あくまで、あなた自身が持ち主の「記憶のグラフ」です。

## 動作要件

- **Node.js** `>=24 <25`
- **Git** — iroha は Git リポジトリの上で動きます
- **Claude Code** `>=2.1.198` と **Codex** `>=0.144.5` のどちらか、または両方

## インストール

iroha は `@irohalabs/iroha` という 1 つの npm パッケージとして配布され、`iroha` バイナリを提供します。このバイナリが CLI・ライフサイクルフック・MCP サーバーのすべてを動かす本体です。だからまずはこれを入れる、それが唯一の必須ステップです。

```bash
npm install -g @irohalabs/iroha
```

あとは、好きな Git リポジトリの中で次を実行するだけ。

```bash
iroha init      # .iroha/ とローカルインデックスを作成（何度実行しても安全。結果はコミットしよう）
iroha doctor    # Node・Git・検出されたエージェント・データベース機能をチェック
```

`iroha` CLI（`init | sync | search | dashboard | doctor`）は、これ単体で完結して動きます。以下のプラグインは、その上にエディタ連携を乗せるものです。

## エージェントの設定

プラグインは、iroha のスキル・ライフサイクルフック・MCP サーバーをエージェントに登録します。どちらのプラグインも、グローバルに入れた `iroha` バイナリを呼び出すので、先に上のインストールを済ませておいてください。

### Claude Code

```text
/plugin marketplace add iroha924/iroha
/plugin install iroha@iroha
```

スキルは `/iroha:init`、`/iroha:sync`、`/iroha:search`、`/iroha:checkpoint`、`/iroha:dashboard`、`/iroha:doctor` として使えます。

### OpenAI Codex

```bash
codex plugin marketplace add iroha924/iroha
```

追加した marketplace から、お使いの Codex のバージョンに合った手順（Codex CLI の `/plugins`）で `iroha` プラグインをインストールします。Codex はプラグインのフックを自動では信頼してくれないので、`/hooks` を実行して明示的に信頼してあげてください。信頼するまでの間も、MCP サーバーと CLI はちゃんと動きます。Codex のスキルは `$init`、`$sync` のように呼び出します。

インストール・更新・アンインストールの詳しい手順（Codex のフック信頼フローを含む）は [docs/install.md](./docs/install.md) にまとめてあります。

## クイックスタート

プラグインを設定したら、あとは「いつも通り作業して、あとで整える」だけ。

```bash
# 1. いつも通りエージェントと作業します。iroha のフックがセッションを観測し、
#    覚えておく価値のあること（決定・ルール・教訓）が出てくると、エージェントが
#    MCP サーバー経由でそれを候補として提案してくれます。

# 2. ローカルダッシュボードで候補をレビューして承認します。
iroha dashboard
#    → http://127.0.0.1:<port>/#token=… が開きます。残したいものを承認しましょう。

# 3. 承認された知識は .iroha/ の下に Markdown ファイルとして保存されます。これをコミット。
git add .iroha && git commit -m "chore: approve knowledge"

# 4. あとはいつでも記憶を検索できます（エージェントは MCP 経由、あなたは CLI から）。
iroha search "なぜ repository パターンを使うのか"
```

リポジトリを clone したチームメンバーは、`iroha init` のあとに `iroha sync --rebuild` を実行すれば、コミット済みの `.iroha/` からローカルインデックスを丸ごと作り直せます。

## 承認ダッシュボード

`iroha dashboard` を実行すると、あなたのマシンの中だけ（`127.0.0.1`）で動く小さな Web アプリが立ち上がり、ブラウザが開きます。開くときには、その場限りの使い捨てトークンが使われます。ここで知識の候補をひとつずつ確認し、出どころやほかの知識とのつながりを見て、「承認」か「却下」かを決めます。承認できるのはこのダッシュボードだけ。あくまで人間が決めることで、エージェントが勝手に承認することはできません。しかもマシンの外には一切公開されないので、ネットワーク越しに誰かに見られる心配もありません。

## 設定

外部と通信する 2 つの機能（セマンティック検索と GitHub 連携）は、**どちらも最初はオフ**です。オンにするには 2 ステップ。まず鍵を登録して、次に `.iroha/config.yaml` でスイッチを入れます。

**1. 鍵を登録する。** ダッシュボードの **設定** 画面を開いて、Voyage / GitHub の欄に貼り付けます。ターミナルから登録することもできます:

```bash
pbpaste | iroha credentials voyage    # macOS。Linux なら xclip -o、ファイルからなら < key.txt
pbpaste | iroha credentials github
```

鍵は `~/.config/iroha/credentials.json`（`$XDG_CONFIG_HOME` があればそちら）に、ファイル `0600` / ディレクトリ `0700` で保存されます。そのディレクトリには `.gitignore` も置かれるので、dotfiles をリポジトリで管理していてもコミットされません。リクエストのたびに読み直すので、差し替えてもエージェントを再起動する必要はありません。CLI は**引数ではなく標準入力から**受け取るため、シェル履歴にもプロセス一覧にも鍵は残りません。iroha が資格情報を環境変数から読むことはないので、`~/.zshrc` に書くものは何もありません。

**2. `.iroha/config.yaml` で機能をオンにする** — このファイルは `iroha init` がすでに作ってくれているので、スイッチ（`enabled`）を `true` にするだけです:

```yaml
search:
  embedding:
    enabled: true    # セマンティック検索。保存済みの Voyage の鍵を使う
forge:
  enabled: true      # GitHub 連携。保存済みの GitHub トークンを使う
```

`config.yaml` はコミットされるファイルですが、秘密の値は一切入りません。保存した鍵を読み出す経路もありません — ダッシュボードも `iroha doctor` も、「設定済みかどうか」しか表示しません。

| 鍵 | オンになる機能 | 未設定だと |
|---|---|---|
| Voyage API キー | Voyage を使ったセマンティック（意味）検索 | 全文検索とグラフ検索だけになる |
| GitHub トークン | GitHub 連携（Pull Request・レビューの取り込み） | GitHub 連携がオフになるだけ |

**鍵の取り方と、気になるコストの話:**

- **Voyage API キー** — [voyageai.com](https://www.voyageai.com/) でサインアップして鍵を作ります。コストはほぼ気にしなくて大丈夫。iroha が使う `voyage-4-large` は **100 万トークンあたり $0.12**、しかもどのアカウントも**最初の 2 億トークンが無料**です（[Voyage の料金](https://docs.voyageai.com/docs/pricing)）。チーム 1 つ分の知識ベースでも、埋め込むのはせいぜい数百万トークン。実際には無料枠を超えることはまずありません。仮に超えても、500 トークンくらいのメモを 1 万件（＝500 万トークン）埋め込んで**たったの約 $0.60**。百円もかかりません！
- **GitHub トークン** — [personal access token](https://github.com/settings/tokens) を作ります。リポジトリの読み取り権限があれば OK です（classic トークンなら `repo` スコープ、fine-grained トークンなら **Contents: Read** と **Pull requests: Read**）。

セマンティック検索が動いていない気がしたら `iroha doctor` を実行してください。鍵が登録されているか、埋め込みに失敗したまま残っているドキュメントが何件あるかを報告します。

ほかに知っておくとよい設定が 2 つあります。

- `default_language` — `en`（既定）か `ja`。ダッシュボードを最初に開いたときの表示言語。
- `canonical.require_human_approval` — `true` のままにしておけば、人が承認するまで、どの知識も正式な知識ベースには取り込まれません。

## 仕組み

1. **どちらのエージェントも同じ形にそろえる。** Claude Code と Codex のセッションを共通の形に変換するので、1 つの記憶グラフで両方をまとめて扱えます。
2. **知識は作業の途中で拾う。** セッションが終わってからまとめて要約するのではなく、作業の区切りごとに拾い上げます（そもそも Codex には、セッション終了のタイミングで動くフックがない、という事情もあります）。
3. **候補には必ず出どころが付く。** 提案される決定・ルール・気づきは、それぞれ元になったソースや、関連するほかの知識にひも付きます。
4. **人間が承認する。** 承認された知識は `.iroha/` の下に Markdown ファイルとして書き込まれ、コミットされます。これがチームで共有する「信頼できる情報源」になります。
5. **検索は手元の libSQL インデックスが支える。** 全文検索はいつでも使えて、セマンティック検索は鍵を設定して有効にしたときに加わります。このインデックスはただのキャッシュ（作り直せる一時データ）なので、いつでも `.iroha/` から再構築できます。壊れても平気。承認済みの知識そのものが消えることはありません。

## よくある質問

**データが外に出ることはある？** 基本、ありません。iroha はローカルファーストで、クラウドアカウントもテレメトリもなし。外と通信するのは、あなたが自分の鍵でオプトインしたときだけ。セマンティック検索の埋め込み（Voyage）と GitHub 連携の 2 つで、有効にするまでは 1 バイトも出ていきません。

**埋め込み用の鍵がなくても使える？** はい、使えます！全文検索とグラフ検索は設定ゼロで動き、日本語などの CJK クエリにもちゃんと対応します。セマンティック検索は、あくまで「あるとうれしい」追加機能です。

**知識はどう保存されるの？** `.iroha/` の中に、Git 管理された素の Markdown として保存されます。ほかのソースコードと同じように読めて、差分の確認もレビューもできます。`.git/iroha/` の中の libSQL インデックスのほうは、ただの使い捨てキャッシュです。

**インデックスを作り直すには？** `iroha sync --rebuild` を実行します。clone した直後は、先に `iroha init` を忘れずに。

**名前の由来は？** *いろは* は、すべての仮名を一度ずつ使う「いろは歌」の冒頭。転じて「物事の基本・いろは」を指します。エンジニアリングの記憶も、まずは基本から。

## セキュリティ

フックによる強制は「ガードレール」であって、完全なセキュリティ境界ではありません。厳密な強制は CI が担います。脆弱性を見つけたら、公開の issue ではなく [security advisory](https://github.com/iroha924/iroha/security/advisories/new) からそっと教えてください。
